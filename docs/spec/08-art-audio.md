# 08 — Art and Audio

How RUSHBLADE looks and sounds, and the code-driven pipeline that makes every image and sound. Read `00-README.md` first (640 × 360, 16 px tiles, 120 ticks/s, architecture).

**This file owns:** art style rules; the art palette (every ramp, the element colors of world art, biome ramps, enemy hue families) and how class colors tint the outfit trim; sprite sizes, anchors and outline rules; draw order; the full animation list (frame counts, fps, how frames are picked from core state); hit, telegraph and status flashes; tilesets and autotiling; parallax backgrounds; darkness rendering; ambient particles; the VFX list; the Python art pipeline in `tools/` (part-based rig, palette lock, atlases, previews, approval), including the art of the `ui` atlas and the bitmap font files; the SFX list and synth; the music system; mixing and browser audio unlock.

**Not here (only referenced):** events and state the view reads (01 §15, 02 §4.6, 03 §14, 04, 05 §15, 06 §16); screen-shake strength and the shake function (01 §14.4); hit-stop lengths and i-frame blinking (02 §4.1, §5.2); enemy sizes, hurtboxes, attacks and timings (04); item names (05); level objects and the collision tileset `kinds.png` (06 §13); every UI color: tokens, grade, class, hybrid, UI element and Dragon text colors, their names, hex values and use (07 §3, copied here unchanged, §3.6); font metrics, charset and use (07 §2); the `ui` atlas frame list and sizes (07 §3.4); HUD layout, icons' placement, damage numbers, volume and shake settings, notice marks (07).

**Code:** `src/game/render/` (views, `animator.ts`, `autotile.ts`, `parallax.ts`, `darkness.ts`, `vfx.ts`), `src/game/audio/` (`sfx.ts`, `music.ts`), `src/data/palette.generated.ts` (written by `tools/art/palette.py`, never edited), `src/data/sfx.ts`, `src/data/musicRules.ts`. Generated files go to `public/assets/` and are committed.

## 1. Ground rules

1. **The view never decides rules.** Every VFX and SFX starts from a core event or from a core state change seen between two ticks (e.g. "the player's attack step id changed"). If a needed value is not exposed, add a read-only getter to core and log a `SPEC-GAP`; never add logic.
2. **View randomness never touches core RNG streams.** Cosmetic variation uses `hash2(x, y, salt)` (§9.2) on tick numbers, entity ids or tile coordinates.
3. **All art and sound are generated by Python 3 + Pillow + numpy scripts in `tools/`.** Outputs are committed and never hand-edited. Same script = byte-identical output (fixed seeds, no timestamps in files).
4. **External assets are optional** and only **CC0** (art, sound, music) or **SIL OFL** (fonts). Each one is listed in `public/assets/CREDITS.md` (name, author, URL, license). Most asset sites are blocked from the cloud containers, so nothing may depend on downloading.
5. **Placeholder first** (plan 12, 14): milestones M0–M7 use placeholder atlases (§12.6) with the final file and frame names; M8 swaps in real art with no code changes.
6. **Approval gate:** before mass production, the user approves the style board (§12.7).

## 2. Style rules

| Rule | Exact requirement |
|---|---|
| Pixel grid | 1 art pixel = 1 game pixel. World sprites are never scaled. Runtime rotation only for: projectiles, the swinging blade, the thrown hammer trail, particles. |
| Light | From the top-left. Each material uses a 3–5 shade ramp (§3). No anti-aliasing on silhouettes. Gradients only as sky bands. Dithering (2 × 2 checker) only in backgrounds and darkness edges. |
| Outline | 1 px `ink` outline outside the silhouette (4-neighbour) on characters, enemies, items, objects, icons and projectiles ≥ 6 px; 07's tint frames have none (§8); outlined fonts use 07 §2.1's 8-neighbour outline (§12.5). Overlapping parts inside a silhouette are separated by the part's darkest ramp shade, never `ink`. Terrain, backgrounds and particles have no `ink` outline. |
| Contrast | Characters are saturated and high-contrast; backgrounds are desaturated and low-contrast, lighter and bluer the farther back. Nothing drawn in front of the player may hide them (no foreground deco in v1). |
| Hue families | The player's body and trim layers use only `p_*`, `skin`, `hair`, `trim` and `ink` (weapons use `w_*`). Enemies are built from their biome's `en_*` ramps (§3.7), plus `ink`, `white`, `skin`, `hair` and small `fx_*`/`gray`/`w_magic` accents (eyes, cracks, gems). **No enemy pixel color except `ink` and `white` may equal any terrain, background or sky color of a biome it appears in** (hard check, §12.8). |
| Telegraphs | Orange = blockable enemy attack, red-magenta = unblockable; the last 0.15 s is a near-white "go" flash (§5.3). Area attacks also get floor markers (§11). |
| Weapons | A weapon is drawn only in attack, charge, block and dive frames. At other times the hands are empty. |
| Fair silhouettes | In the idle frame, the opaque silhouette edges are within ±2 px (player) or ±3 px (enemies) of the hurtbox edges (01 §2.2, 04). Checked on the preview overlay (§12.7). |

## 3. Palettes

### 3.1 Master palette and palette lock
- `tools/art/palette.py` holds every color below as named **ramps** (dark → light). It also writes `src/data/palette.generated.ts` (every ramp color as `0xRRGGBB` numbers) so game code and tools share one source for art colors. UI colors are 07's (§3.6).
- **Sky ramps** are 6 bands made by linear sRGB interpolation from `top` to `bottom`, each channel rounded half up.
- **Palette lock:** each atlas declares its allowed ramps. Every pixel of every generated PNG must be fully transparent (alpha 0) or opaque (alpha 255) with an RGB in the allowed set. Any other pixel fails the build with `atlas, frame, x, y, color`. Never auto-quantize. Exceptions: soft light textures (§10.2) may use alpha 0/64/128/192/255.

## 5. Animation system

### 5.1 Clocks (never Phaser's animation clock)
- Frames are picked every render frame from core state, so hit-stop freezes them and replays match exactly.
- **Time-driven** (`loop`, `once`): `i = floor(t × fps)`; `loop` uses `i mod n`, `once` uses `min(i, n − 1)`. `t` = seconds in the current anim. Player: `stateTicks / 120` where the anim follows a movement state, otherwise the view's own anim time.
- **View anim time:** each render frame, add `ticksAdvanced × (1/120) × timeScale` (enemy `timeScale` from 02 §6.3, which includes Time Slow) unless the entity is in hit-stop. Reset to 0 when the anim key changes.
- **Phase-driven** (`phase`): the anim lists segments in phase order, each with frame indexes. Inside a segment of `k` frames with progress `p = elapsedTicks / phaseTicks`, show `frames[min(k − 1, floor(p × k))]`. A segment with `loopFps` cycles instead. Inputs: the phase, its elapsed ticks and its total ticks (player step from 02, cast from 03 §7.6, enemy attack from 04). Attack speed changes `phaseTicks`, so animations speed up with Rush automatically.
- **Speed-driven** (`run`): fps = `clamp(14 × abs(vx) / 170, 8, 24)`; accumulate `fps × dt` and wrap.

### 5.2 Player anim choice (first match wins)
`dead` → `hurt` → active weapon step / charge / shield / throw → active ability pose (§6.2) → `drink` → movement state (§6.1). Air attacks use the same frames as ground attacks.

### 5.3 Overlay flashes (one overlay sprite per character, same frame, solid fill)
Solid fill = every opaque pixel becomes the overlay color (Phaser 4: tint mode FILL; in Phaser 3 this was `setTintFill`). Priority, highest first:

| Overlay | When | Color, alpha |
|---|---|---|
| Hit flash | A direct hit lands on an enemy or the player: for the longer of 6 ticks and the target's hit-stop | `white`, 1.0 |
| Telegraph "go" | The last 0.15 s of enemy time (18 ticks at `timeScale` 1) of any enemy Tele (04 §2.6) | #fff4c8, 0.85 |
| Telegraph | The rest of the Tele: alpha is a triangle wave 0.15 → 0.55 → 0.15 with period 0.2 s | #ff8a1f; unblockable attacks #ff2e6a |
| Frozen | While Frozen (02 §6.3); the anim frame also stops | `fx_ice` #8fdcff, 0.5 |
| Status tint | Burning #ff7a2e, Chilled #8fdcff, Poisoned #78d94a, Rage #e8484f (pulse 4 Hz), Hunter's Mark none | 0.2 |
| Spawn-in | The 0.5 s spawn-in (04 §2.2): body alpha 0 → 1 linearly, overlay `fx_dark` #6a3a94 0.8 → 0 | |

- Player i-frame blinking is 02 §5.2 (alpha). Teleport fades (Shaman, Battle Mage, King) set body alpha 1 → 0 → 1 over their listed times.
- **Hit-stop jiggle:** an enemy in hit-stop is drawn 1 px left and right on alternate ticks (view offset only).

### 7.2 Attack frame rule
Frames = Tele `[0, 1]` + Act + Rec `[last − 1, last]`. Act is: 1 frame normally; **2 frames looped at 12 fps** for attacks with a Move; **2 frames picked by `vy`** (rising f0, falling f1) for Leap and Jump-to-X; **4 frames looped at 16 fps** for spins (Whirling Axe, Quad Slash hit 4). Each `chain` hit adds 2 frames (its Tele 1, its Act 1) before Rec. Example: Knight Sword Combo = 2 + 1 + 2 + 2 = 7 frames.

## 9. Tiles and autotiling

### 9.1 Tileset files
One `public/assets/tiles/tiles_<set>.png` per terrain set (`plains`, `mountains`, `swamps`, `kingdom`, `castle`). The map's `biome` property (06 §13.2) picks art: a stage uses its own set; `home` and `crossroads` use `plains` tiles, `border` uses `mountains`, `rebel_camp` uses `kingdom`, each with its own `village_*` background (§3.7). 16 columns × 9 rows of 16 × 16 tiles, **margin 1, spacing 2**, each tile's edge pixels extruded 1 px into the gap (no seams). Phaser: `addTilesetImage(name, key, 16, 16, 1, 2)`.

| Rows | Content |
|---|---|
| 0–2 | Solid blob tiles, index 0–46 (column = i mod 16, row = floor(i / 16)) |
| 3 | Cols 0–3: extra full-center variants · 4–6: one-way left, middle, right · 7: one-way single · 8–11: spikes up, right, down, left · 12: cracked wall · 13: blink-block overlay · 14: collapsing solid · 15: collapsing one-way |
| 4–6 | Ice blob tiles, index 0–46 |
| 7 | Cols 0–3: water surface frames · 4–7: water body frames · 8–15: top deco variants |
| 8 | Cols 0–7: hanging deco variants · 8–15: spare (empty) |

Level decoration layers (06 §13.3) use gid `g ≥ 17` → tile index `g − 17` of this sheet.

### 9.2 Blob autotiling (pure function `autotile.ts`, unit-tested)
- `filled(tx, ty)` = out of map bounds, or kind `solid` or `ice`. Bits: N 1, NE 2, E 4, SE 8, S 16, SW 32, W 64, NW 128.
- **Reduce:** keep each diagonal bit only if both of its neighbouring cardinal bits are set. The 256 masks reduce to exactly **47** values; sorted ascending they are blob indexes 0–46 (mask 0 → 0, 85 → 21, 124 → 31, 255 → 46). `tools/art/tiles.py` draws each blob tile from its reduced mask with the same rule, so both sides agree.
- Solid cells use the solid blob, ice cells the ice blob. Mask 255 picks a variant: `v = hash2(tx, ty, 1) mod 5`; `v = 0` is blob tile 46, `v = 1–4` are row 3 cols 0–3.
- Drawing per tile: exposed top edge = 3 px cap (grass, snow, moss, roof edge, carpet edge per set) + 1 px highlight; exposed sides and bottom = 1 px rim in the ramp's darkest shade; inner corners notched 3 × 3.

```ts
function hash2(x: number, y: number, salt: number): number {   // cosmetic only, never core RNG
  let h = (Math.imul(x | 0, 374761393) + Math.imul(y | 0, 668265263) + Math.imul(salt | 0, 1442695041)) | 0;
  h = Math.imul(h ^ (h >>> 13), 1274126177);
  return (h ^ (h >>> 16)) >>> 0;
}
```

### 9.3 Other tile kinds
- **One-way:** left end / middle / right end chosen by whether the left and right cells are `oneway`; single when neither. The art fills only the top 6 px of the cell.
- **Spikes:** the matching row 3 tile, on the terrain layer.
- **Water:** a separate tile layer at depth 75, alpha 0.65, so wading legs look submerged. A water cell whose upper cell is not water uses a surface tile, else a body tile; both animate 4 frames at 6 fps with frame `(f + tx) mod 4`.
- **Bodies** (cracked walls, blink blocks, collapsing platforms) are sprites drawn from the tileset image loaded as a spritesheet (same margin and spacing), one per 16 px cell.

### 9.4 Auto-decoration (view only, deterministic)
For each empty, non-water cell: if the cell below is `filled`, place top deco variant `hash2(tx, ty, 2) mod 8` when `hash2(tx, ty, 3) mod 100 < 30`; if the cell above is `filled`, place hanging deco `hash2(tx, ty, 4) mod 8` when `hash2(tx, ty, 5) mod 100 < 20`. Depth 10. Never in villages (their deco is hand-placed props).

### 9.5 Minecart rails
For each `minecart`, march 16 px columns from its spawn x in `dir` until a column overlaps a `minecart_stop`. In each column, draw a rail on the topmost `solid`, `ice` or `oneway` surface whose top lies between 32 px above and 48 px below the previous rail top (first column: the cart's feet y). No surface in that window → no rail in that column.

### 12.1 Layout and commands


Flags: `--only <glob>` rebuilds matching atlases; `--placeholder` builds placeholder art (§12.6). Every random choice uses `numpy.random.default_rng(crc32(asset_id))`.

### 12.2 Raster primitives
`raster.py` works on numpy arrays of palette indexes (−1 = transparent): `fill_polygon` (pixel centers inside), `capsule(p0, p1, width)`, `ellipse`, `line` (Bresenham), `stamp(grid)`. **Auto-shading per part:** a pixel whose up or left neighbour is outside the part takes the ramp's light shade; down or right outside → dark shade; the rest base shade. **Outline pass** after compositing (§2). Hand-typed character grids are allowed only for small stamps (≤ 16 × 16: faces, hats, hands, weapon heads, icons' details).

### 12.3 Part-based rig
- **Humanoid skeleton** (frame px, feet at the anchor, facing right): hip 12 px above the feet; hip → shoulders 8; head center 5 above the shoulders (8 × 8 head); upper arm 5, forearm 5; thigh 6, shin 6. Joints: hip, chest, head, shoulder/elbow/hand front and back, knee/foot front and back.
- **A pose** is data: `{lean, hipOffset [dx, dy], head [dx, dy], armF [shoulderDeg, elbowDeg], armB [...], legF [hipDeg, kneeDeg], legB [...], weapon {angle, hand: 'F' | 'B' | 'both'}, weaponBehind}`. Forward kinematics gives joint positions; angles in degrees, 0° = straight down.
- **Draw order:** back arm, back leg, torso, front leg, head, front arm. Back limbs use one shade darker than front limbs. Then the outline pass. Trim parts are drawn into the trim A / trim B layers using the same pose and the same occlusion (trim pixels hidden by the front arm are removed).
- **Consistency:** every outfit reuses one pose table (`poses/player.py`); outfits only swap parts and widths. Humanoid enemies reuse the skeleton with their own lengths. **Quadruped rig** (Wolf, War Hound, Wild Boar, Ram, Great Boar): body ellipse, neck + head, 4 two-segment legs, tail. Bat Swarm, Spider, Wisp, Treant, Gargoyle and Dragon have their own part sets on the same raster tools.
- Frame pixel counts are integers only; joint positions are rounded half up after FK.

### 12.4 Weapons and smears
- A weapon is a list of segments along its axis from the grip (handle, guard, blade, head …), each `{length, width, ramp, shape: 'rect' | 'taper' | 'disc'}`, drawn at the pose's weapon angle **snapped to the 16 clean directions** (slopes 0, ½, 1, 2, ∞ in every quadrant), then auto-shaded and outlined.
- **Smear:** the area swept by the weapon from frame S1 to frame A, sampled at 6 intermediate angles about the grip and unioned. Outer 40% of the radius `#ffffff`, the rest `#b0b0b0`, no outline. The A-frame pose should make the smear cover 02's hitbox; the preview overlays that box (§12.7).

Phaser JSON-hash format: `frame`, `rotated: false`, `trimmed: false`, `spriteSourceSize`, `sourceSize`, `meta.image`.
- Frame names: `<animKey>_<NN>` (two digits, from 00), smears `<animKey>_smear`.

## 13. Sound effects

### 13.1 Format and synth
- WAV, PCM 16-bit, 44,100 Hz, mono, ≤ 2.0 s, peak normalized to **−1 dBFS**, 1 ms fade-in and 5 ms fade-out (first and last samples within ±64). Files: `public/assets/audio/sfx/<id>.wav`, variants `<id>_1.wav`, `<id>_2.wav` ….
- `tools/audio/synth.py` is a small sfxr-style synth in numpy. A recipe is a list of layers mixed together; each layer: wave (`sq` square with duty, `saw`, `tri`, `sin`, `nz` white noise), start → end frequency (exponential slide), attack / sustain / decay seconds, optional vibrato (depth in semitones, rate Hz), arpeggio steps, one-pole low-pass / high-pass with start → end cutoffs, bit-crush, and a level. Variants re-run the recipe with a different seed and ±4% frequency.
- Recipe shorthand below: `sq.25 280→520 80ms` = square, duty 0.25, 280 to 520 Hz, 80 ms; `lp 2k→600` = low-pass cutoff sweep; `+` = another layer.

### 13.2 Playback rules (`src/game/audio/sfx.ts`)
- Triggers are core events or state changes. Each id has: `vol` (0–1, below), `maxVoices` (default 3; hits 4; footsteps 1; UI 1), `minGap` 0.03 s per id, bus `sfx` or `ui`.
- Variant: round robin per id. Pitch jitter ±3% from `hash2(tick, idHash, 7)`.
- **World sounds** from enemies and hazards: pan = `clamp((x − camCenterX) / 320, −1, 1) × 0.5`; volume × `clamp(1 − (d − 320) / 320, 0, 1)`, d = horizontal distance to the player. Player sounds are centered.
- Element layer: an element hit plays the hit sound plus the element sound at ×0.5, at most once per 0.05 s per element.
- 32 voices max; when full, the quietest world sound is stopped.

## 14. Music

### 14.1 Approach: data + a WebAudio step sequencer (works offline, tiny files)
- Music is **note data** (`public/assets/music/<track>.json`) played by `src/game/audio/music.ts` with **instrument samples** (`public/assets/audio/inst/<id>.wav`) generated by `tools/audio/instruments.py`. No compressed audio and no encoder are needed, and Rush layers stay sample-accurate.
- Tracks are composed in Python (`tools/audio/music/<track>.py`) with helpers (drum strings like `"x...x...x..x.x.."`, chord progressions, arpeggiators) and exported to JSON. `render_music.py` renders `tools/out/preview/music_<track>.wav` (30 s) so the user can listen and approve.
- **Scheduler:** a 25 ms timer schedules every note that starts within the next 0.10 s on the AudioContext clock. Step length = `60 / (bpm × tempoMult) / 4` s (16th notes). After the last step the track jumps to `loopStartBar`. A tempo change takes effect at the next bar line.
- **Voices:** `AudioBufferSourceNode` with `playbackRate = 2^((midi − rootMidi) / 12)` → note gain (attack 5 ms, release per instrument, cut at the note's length) → channel gain → layer gain → music bus. Max 24 music voices; the oldest is cut.

### 14.2 Instruments (all 2.0 s long, `pad` and `strings` 4.0 s; max note length = sample length)
`kick` (sin 150→45 Hz + click, root 36) · `snare` (nz bp 1.8k + tri 190 Hz, 38) · `hat` (nz hp 7k 40 ms, 42) · `hat_open` (200 ms, 46) · `tom` (sin 160→90, 45) · `bass` (saw lp 900, 36) · `lead` (sq.25 + 5 Hz vibrato after 150 ms, 60) · `pluck` (Karplus-Strong, 60) · `pad` (3 saws ±7 cents, lp 1.2k, attack 0.3 s, 60) · `bell` (FM sine ratio 3.5, 72) · `strings` (2 saws, attack 0.15 s, lp 2.5k, 60) · `brass` (saw lp 600→2400, 60) · `arp` (sq.125 250 ms, 72). `instruments.json` lists `{id, file, rootMidi, release}`.

### 14.4 Rules (`src/data/musicRules.ts`)
- **Rush layers** (stage tracks): L1 on at Rush ≥ 1, L2 at ≥ 2, L3 at 3 (02 §8.1). Turning on: gain 0 → 1 over 0.5 s. Turning off: only after the level has been lower for 1.0 s, then 1 → 0 over 1.5 s. `tempoMult` = 1.00 / 1.02 / 1.04 / 1.06 for Rush 0–3 (next bar line). Boss tracks ignore Rush.
- **Switching:** stage start → stage track from bar 1. `arenaLocked` of a **boss** arena → stage track fades out 1.0 s, boss track starts (combat arenas change nothing). Dragon awake → crossfade 1.0 s to `boss_dragon`; Dragon passive → crossfade back to the stage track from `loopStartBar`. `bossDefeated`: Guardian or Black Knight → fade 0.5 s, `sting_victory`, then silence (ambience only) until the village; Dragon → `sting_victory`, then the stage track from `loopStartBar`; Enemy King → `sting_complete` only, then `title` on the summary. `enterVillage` → `village` fades in 1.0 s (the Home Village too; the title screen plays `title`). `playerDied` → fade 0.2 s, `sting_death`. Instant restart → `plains` from bar 1.
- **Pause** (07): music continues at ×0.35; all SFX pause and resume.
- **Time Slow** (03): music through a 900 Hz low-pass; enemy and hazard SFX play at rate 0.75. Both restore at the end.

## 15. Mixing and browser audio

- **Buses:** master → music (trim 0.55), sfx (trim 0.85), ui (trim 0.60). The user's master, music and sfx volumes (07 settings) multiply these; the ui bus follows the sfx volume.
- **Ducking:** `boss_roar_*`, `dragon_roar`, `jackpot` and all stingers duck the music bus by ×0.5 (attack 0.05 s, release 0.3 s after the sound ends).
- Hit-stop does not pause or delay audio. Sounds start on the render frame that sees their trigger.
- **Unlock:** use Phaser's WebAudio sound manager and its AudioContext for both SFX and the music scheduler. The scheduler starts on the manager's `unlocked` event. Browsers unlock audio only on a key press, click or touch; **a gamepad button does not unlock audio**, so 07's title screen must keep its "press a key or click" prompt until `sound.locked` is false. Before unlock, nothing is queued (no backlog of sounds plays later).
- The game must run with no audio at all (unlock never happens): all audio calls are no-ops until then.
