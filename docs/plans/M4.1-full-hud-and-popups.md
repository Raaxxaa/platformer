# M4.1: Full HUD and Popups — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** M4 was finished before the playtest HUD feedback reached its plan, so it built only the slot HUD. This plan adds the rest: the **real HUD** with a big health bar, flask, gold and Rush; the **item card** that shows what you get when you pick up an ability or weapon; the framed popups; and a **pause menu with tabs** (`MENU`, `LOADOUT`, `CONTROLS`). It also swaps in ART5's art once it's on `main`.

**Spec:** `docs/spec/07-ui-hud-controls.md` §3.4 (the `ui` atlas, now 103 frames with the popup skin), §4 (HUD, new layout in §4.1: HUD plates, heart, 160 × 12 HP bar), §6.1–6.3 (item card, swap choices), §6.7 (class pick), §7.6 (pause with tabs), §9.2 (blurbs, including bonds and hybrids).

**Starting point:** M4 on `main`. Merge `main` and `origin/claude/great-dijkstra-g00pcj` first.

## Global Constraints

- All earlier constraints hold. The UI never decides game rules; it reads core state and events (07 §1.4).
- Keep M4's slot HUD code and extend it; positions now come from 07 §4.1 exactly.
- If a `ui` frame isn't in the atlas yet (ART5 Task 8 adds 9 frames), draw 07 §1.1's placeholder rectangle for it.
